# Bing SEO 90 天运营计划

目标：先收录、再展示、后点击。每个阶段都看四个独立指标：IndexNow 提交成功数 / Bing 已抓取数 / Bing 已收录数 / 搜索展示与点击。

## 第 1–2 周：上线与收录基础

| 任务 | 完成标准 |
|---|---|
| 录入 34 家品牌名称与 AFF 链接 | `npm run check:data:strict` 通过 |
| 前四家至少核实 1 个套餐价格并标 verified | 资料页显示真实价格与核实日期 |
| 部署、绑定域名、www 跳转 | `curl -I` 检查 301 与 HTTPS |
| Bing 验证 + 提交 sitemap + IndexNow 全量提交 | BWT 显示 sitemap 成功；IndexNow 200/202 |
| 同步在 Google Search Console 验证与提交 | GSC 显示 sitemap 成功 |
| URL 检查抽查 5 个页面 | Bing 能看到完整正文 |

**指标记录**：第 7 天、第 14 天各记录一次收录数（`npm run bing:status`）。

## 第 3–6 周：补全资料与内容深化

- 每周核实 4–6 家机场资料（价格、流量、线路、客户端、限制），写入 changelog。
- 前四家补全全部 12 个字段。
- 每周新增 2 篇文章，先查 `keywords.ts` 避免重复，建议方向：
  - 各平台 Clash Meta for Android 教程
  - 规则分流入门（规则模式、全局模式、直连的区别）
  - 机场跑路风险与识别方法
  - 外区 Apple ID 注册注意事项
  - 路由器 / 软路由使用机场（进阶）
  - 机场倍率、限速、设备数等名词解释
- 每篇新文章：在 2 篇相关旧文章中添加内链；发布后自动 IndexNow。
- 从 Bing 搜索性能找出 **平均位置 8–20** 的关键词，优化对应页面 title/description 和首段。

**指标**：已收录页面 ≥ 80% 的 sitemap URL；目标关键词中至少 10 个出现展示。

## 第 7–10 周：点击率与权重

- 展示多、CTR 低于 2% 的页面：重写 title（突出“2026”“核实日期”“每GB价格”等具体信息），每次只改一处，观察两周。
- 将榜单、资料核验页的更新频率固定为每两周一次，并更新 `updated` 日期（只在内容真正变化时）。
- 外部信号：在 Telegram 频道、相关论坛以“工具”（流量估算器、每GB计算器）为切入点分享，获取自然引用。不购买链接、不发垃圾外链。
- 检查 Bing 站点扫描结果，修复所有错误级问题。

**指标**：“机场推荐”“梯子推荐”等核心词进入前 30；整体 CTR 提升。

## 第 11–13 周：复盘与扩展

- 全站资料复核：超过 90 天未核实的资料重新核对。
- 对比关键词实际落地页与 `keywords.ts`，处理内部竞争（合并或改写相似页面，301 旧页面）。
- 根据搜索词报告中的新长尾词规划下一季度 12 篇文章。
- 评估是否为前五品牌各写一篇“使用一个月后”的真实体验文章（只写可以证实的事实）。

## 每周固定动作（约 1 小时）

1. `npm run bing:queries` 导出搜索词，记录核心 25 词的展示、点击、排名；
2. 查看 BWT 抓取错误；
3. 处理 Telegram 上的读者纠错；
4. 至少更新 1 处真实变化的资料。

## 不要做的事

- 不批量生成相似文章，不在多篇文章重复堆砌同一批关键词；
- 不伪造测速、评分、用户评价；
- 不为了“更新时间”而修改日期却不改内容；
- 不把推荐顺序描述为测速排名。
